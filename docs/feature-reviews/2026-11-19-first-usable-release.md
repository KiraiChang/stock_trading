# 2026-11-19 功能檢討：首次功能盤點與可用首版

本期建立基準。盤點日期為 2026-11-19（台北），程式基準為 `4fedd52`。範圍包含現有前端、API、資料流程與已記錄的部署驗收。相關前端測試 36 項通過，涵蓋 SR 頁面與交易分析、持倉的 API 呼叫。首版完整瀏覽器操作與連續交易日試用仍待驗證。

## 本期判斷

**第一版建議做「台股盤後交易計畫」，以自用為主。** 從觀察清單選一檔股票，看到目前的判斷、理由、接下來要觀察的條件，以及行情日期。隔天仍可回看原本的計畫。

專案已能把支撐壓力、進場許可、風險報酬與實際持倉接起來，針對空手與持有產生不同分析並保存快照。首版要驗證的價值是能否減少切換頁面與重複判斷，並讓使用者事後說得出當時為什麼等待或改變觀察重點。見 [系統定位](../architecture.md#系統定位) 與 [交易分析 API](../api-reference.md)。

## 可用首版的交付與驗收

1. **接通入口。** 觀察清單可直接開啟選中標的的交易計畫。已有投組時沿用選擇，沒有投組時引導建立。
2. **顯示資料是否可用。** 分開標示行情日期、分析紀錄時間與歷史快照。明確區分等待確認、資料不足與更新失敗。更新失敗時，既有計畫仍可標為歷史供回看。
3. **用實際流程驗收。** 登入後從觀察清單兩步內看到單檔計畫。核對空手、持有、等待確認與資料過期四種情境。新日 K 到了，計畫可刷新並顯示新日期。測試刷新失敗及切換股票時的畫面，確認舊計畫不會被誤認成新標的的判斷。

進階警報、擴大標的池、整套風控與配置功能留待後續檢討。首版維持人工判斷的定位。

## 下一期回看

建議在首版可操作後，用固定的小份觀察清單試用 5 個交易日。每天記下從開啟清單到做完盤後檢查的耗時、是否還需要跳到其他頁面，以及有沒有看不懂或用到過期資料的案例。下一期用這些紀錄判斷入口是否省時、計畫是否有足夠資訊，以及下一個缺口要補在哪裡。試用先衡量流程的可用性，策略成效另循既有離線驗證。
