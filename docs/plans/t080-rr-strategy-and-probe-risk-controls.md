## 一、目的與邊界

把「RR 算得對不對、交易條件是否合格、合格後可以投入多少、多久能再交易」集中規劃，讓少量試單有明確的資金、風險與頻率定義。
本案的效益要以計算正確性、風險提示的一致性與含成本的模擬結果驗證；不能把提高 RR 或縮小部位直接當成提高漲跌預測準確度。
系統提供建議股數、金額與預計風險，由使用者人工判斷及下單；建議額度不是實際資金鎖定，也不能強制限制使用者在券商端的交易。

本案涵蓋：

1. Setup RR、Executable RR、持倉 RR 的計算口徑、價格來源與進場門檻，包含成本與滑價如何納入。
2. 試單部位比例、單筆／單檔金額及風險預算、依資產或預計投入資金百分比浮動的額度、加碼與停止加碼條件。
3. 有可靠交易紀錄時的試單頻率、同股冷卻、連續虧損暫停新增建議及恢復提示。
4. 依已登錄持倉與資金估計同一 portfolio 的總曝險；未掌握的外部交易狀態須明示資料限制。
5. Python 許可、Go 建議股數、前端呈現與人工帳務紀錄的一致性及可追溯性。

I-129 負責 RR 資料流及進場許可的一致性。其試單放寬方案量測未通過後已退回等待確認；本案沿用這項邊界，
不因為新增部位或頻率限制，就視為已滿足重新開放試單的條件。若要恢復該放寬，要先完成 T-002 的時間外驗證（I-129 跑測分析 review 的 R1）與 I-130 的成交歸因與量測口徑補強（R2～R4），再依 I-130 計畫書事前裁決的新版放行判準判定（2026-11-10 使用者裁決）。新版判準要寫明結果類型、分母與成本情境版本，並綁定 T-002 的驗證資料，⛔ 不能讓「成本前通過、成本後為負」的情況放行；I-129 的舊判準只當回歸比較。

**分工**（2026-11-10 使用者裁決）：量測工具的口徑與輸出（訊號價／成交價 RR、不利偏移範圍、結果類型與成本前後的 R）由 I-130 負責，模型的時間外驗證由 T-002 負責；本案負責策略的使用方式——成本假設、可接受進場價格、失效提示與試單參數——並拿那兩項的量測成果裁決，⛔ 不在本案修改量測工具。T-081 維持資產配置範圍。

**成本設定的先後**：

1. I-130 在量測前先確認一版**量測用成本情境**：商品類別、股數基準、手續費與交易稅、最低收費、滑價，帶版本號寫進報告。⛔ 不必等本案全部完成。
2. I-130 用這一版計算成本前後的結果。
3. 本案拿 I-130 的結果評估策略，裁決實際使用時的成本假設；跟量測用的那一版不同時，就是新的成本情境版本，要另出報告，⛔ 不覆寫既有報告。

「3.1」列的費率與成本口徑，是本案第 3 步要裁決的內容，⛔ 不是 I-130 量測的前置條件。

本案目前不決定新的交易比例、次數、冷卻時間或稅費數值，也不授權實作、調整正式設定或部署。

## 二、已查證的現況

以下是 2026-11-05 的 repository 盤點，不代表已核對 live 的環境覆寫或實際券商委託。

| 面向 | 目前行為與來源 | 規劃上要釐清的邊界 |
|---|---|---|
| 交易區統計 RR | [scoring.py](../../python/backtest/modular/sr_scoring/scoring.py) 使用角色解析後的平均反彈報酬與平均跌破報酬，`risk_reward_ratio = abs(expected_gain / expected_loss)`；分母為 0 時不產生 RR | 這個比值沒有乘上勝率；與模型機率、EV 分開解釋 |
| 預計進場 RR | [decision_engine.py](../../python/backtest/modular/sr_scoring/decision_engine.py) 的 `_rr_context()` 使用 `(target - entry) / (entry - stop)`；目標封頂於第一道可量化前方壓力，缺目標時保持未知 | 按預計價格計算，不是已成交報酬；此價格距離公式未扣費稅與滑價 |
| RR 門檻 | `_minimum_rr()` 依 entry 類型、tier 與 role 決定，現有值為 1.5／1.8／2.0；完整進場另有 2.0 門檻 | 新案先盤點來源與優先順序，不能只看單一 RR 數字推論一定可買 |
| Python 試單許可 | `PROBE_ALLOWED`／`BuySmall` 表達進場許可與建議；I-129 退回後 setup 不合格不放行，結構性阻擋仍保留 | 許可標籤本身沒有指定股數、金額或每日次數 |
| Go 部位上限 | [analyzer.go](../../backend/internal/portfolio/analyzer.go) 的 `buildSnapshot()` 取金額允許股數與風險允許股數的較小者；[config.yaml](../../backend/config.yaml) 的 `position_analysis` 目前為單檔金額 200,000、預計風險 10,000 | 這是持倉分析中的單檔建議計算，不是跨股總額度，也不是實際虧損保證上限 |
| 無持倉時的試單股數 | `BuySmall` 且 Go 的 `canIncrease` 成立時，目標股數為 `floor(fullTarget * 0.5)` | 50% 是目前程式內固定比例，並非本案已核准的未來標準；股數還受停損距離與取整影響 |
| 有持倉時的加碼 | 新格式主要依 `position_action` 與持倉風險處理；`AddOnRatio` 的買進／試單加碼分支限 legacy 決策 | 不能把設定中的 0.25 解讀成所有新格式訊號都會再加碼 25% |
| 現有持倉帳本 | [position_repo.go](../../backend/internal/store/position_repo.go) 及 [Position Analysis API](../api-reference.md) 已有 BUY／SELL／ADJUSTMENT；保存股數、價格、fee、tax、occurred_at 與 position version | 帳務登錄不等於已驗證的券商成交回報；ADJUSTMENT 是帳務校正，不能當作一次成交 |
| 試單頻率與總曝險 | 本次查閱的 I-129 計畫與持倉分析流程沒有專門的每日試單計數、同股冷卻、連續停損暫停及跨股風險預算 | 須先確認人工紀錄與資金資料的完整度；不能由分析快照次數代替成交次數，也不能宣稱掌握所有外部委託 |

既有股數公式如下；50% 及既有設定只用於記錄現況：

```text
金額允許股數 = floor(MaxPositionValue / current_price)
風險允許股數 = floor(MaxRiskAmount / (current_price - support.PriceLow))
完整部位股數 = max(0, min(金額允許股數, 風險允許股數))
無持倉的試單建議股數 = floor(完整部位股數 * 0.5)
```

Go 另以當下支撐／壓力計算 RR；沒有上方壓力時，可用 `BreakoutTargetRR` 推導目標。
這與 Python「沒有可量化目標則 Executable RR 未知」的口徑不同。正式方案要列出各自用途與權威來源，
不能讓 Go 的估計目標默默覆蓋 Python 的進場等待或阻擋。

## 三、待設計的策略與計算契約

### 3.1 RR、成本與價格來源

* 分開定義統計 RR、預計進場 RR、持倉 RR 與成交後實現 R；標明價格時間、資料版本與用途。
* 釐清 Python 與 Go 的 entry／stop／target 來源、無目標時的語意、門檻優先順序及最終進場仲裁位置。
* 決定是否同時輸出毛 RR 與扣成本後的淨 RR，並列明手續費、最低收費、交易稅、買賣價差與滑價假設。
  費率須按商品、券商與適用日期確認；本紀錄不指定新數值。
* 若成本隨股數非線性變動，股數取整後要重算成本與 RR，避免先用固定每股成本算出過大的部位。
* 缺 entry／stop／target、風險不為正或資料過期時，輸出要能表達未知與原因；不能以統計 RR 反推缺少的真實價格。
* 高 RR 不等於高勝率；若把模型機率納入策略，要獨立列出 EV 與校準要求。

### 3.2 試單部位與加碼

* 決定「少量」的基準：完整允許部位的一部分、固定金額、portfolio 淨值比例或單筆風險預算。
* 建議股數上限要同時考量已知持倉、可用資金、單檔剩餘額度、單筆風險及跨股總額度，並標示各項資料時間與完整度。
* 釐清試單上限是「本次建議新增」還是「依已登錄紀錄估計的累計持有」；未登錄交易的影響須明示，不能宣稱限制已在券商端生效。
* 每次分析是依指定資料的估算，讀取、刷新或產生建議不扣資金、不預留額度，也不建立成交紀錄。
* 定義最小交易單位、股數取整、零股與不足最小單位時的結果，不能為了產生建議而強制補成一股。
* 加碼須有獨立條件與總額度重算；原有試單許可不能無條件當成再次加碼授權。

### 3.3 頻率、冷卻與連續虧損

* 頻率與連虧提示依人工登錄交易計算，完整交易如何分組仍待定案；紀錄不足時顯示無法判定，不推定為零次交易或零虧損。
  分析／提示次數與交易次數分開；重複讀取／建立分析快照不能直接當成再次成交。
* 範圍至少分清 `portfolio_id + symbol` 的同股限制，以及 portfolio 整體限制；同一使用者的多個 portfolio 是否共用額度待裁決。
* 定義單日、滾動時間窗或交易日窗口，以及台北時區、休市日、跨日與冷卻到期的判定。
* 定義冷卻從已登錄的成交、停損或清倉何時起算，以及何時恢復新增建議；重啟服務與快照刷新不能清空已有紀錄推導的狀態。
* 定義連續停損／虧損的單位與淨損益來源，包含部分賣出、分批進出、費稅、帳務補登及歷史更正。
  ADJUSTMENT 不能直接當成一次交易，也不能被用來重設虧損紀錄。

### 3.4 總曝險估算與風險提示

* 總曝險需定義按持倉市值、停損風險金額或兩者估算，並說明缺停損或價格時的處理。
* 評估產業／相關性集中度的資料可得性與是否納入首版；這部分尚未定為現行限制。
* 盤點使用者提供的可用資金、已登錄持倉與交易資料的來源、更新時效及涵蓋範圍；目前帳本不足以證明已掌握所有券商未成交委託。
* 若使用者另提供預計保留資金，可評估作為人工情境輸入；本期不建置券商委託追蹤。缺資料時不能默認外部曝險為零。
* 單股分析各自顯示的建議額度不能直接相加當成多股可同時投入的金額；若要比較多股方案，須在同一資金快照下試算組合並揭露共同預算。
  這是情境計算，不是額度預留或原子扣抵。
* 資料不足時，仍可呈現有效的價格／RR 分析與條件式試算；缺少依據的個人化股數、總曝險或頻率結論則須顯示無法判定。
* 預算用盡、冷卻、連虧及可選的虧損／回撤門檻，只影響新增部位建議與提示；減碼／退出風險資訊另保留，不執行買賣、撤單或強制清倉。
  虧損與回撤提示須定義已實現／未實現損益及入出金口徑，具體門檻與恢復條件待裁決。

#### 3.5.1 計算規格、精度與標準案例（2026-11-05，v5）

**目的**：讓相同價格、資金與政策產生可核對的結果，避免 Python、Go 與前端各自解讀 RR、百分比或股數，導致建議互相矛盾。

**輸入與建議行為**：

* 列出 Setup RR、Executable RR、持倉 RR、EV 與實現 R 的用途、公式及必要資料，不能把不同指標當成同一數字。
* 每個 entry／stop／target 與資金基準都須有來源；明定誰產生價格與許可、誰計算股數、誰作最終建議仲裁，前端只按已定契約呈現。
* 固定金額、價格、股數與比例的單位、有效範圍、運算精度及取整方向；例如畫面輸入的 5% 如何轉成運算比例，須有唯一規則。
* 股數取整後重算費稅與預計損失。建立獨立人工計算的標準案例，跨層以同一組輸入核對，避免測試只複製程式公式。

**資料不足或異常時**：缺目標價時不能產生確定的 Executable RR；entry 不高於 stop 時不能用零／負風險推算巨大股數。
毛 RR 可算但成本未知時，只顯示毛 RR 與成本未核實，不能將毛 RR 標成已扣成本合格。

| 候選驗收案例 | 預期結果 |
|---|---|
| entry＝100、stop＝95、target＝110 | 毛 Executable RR＝2；畫面與分析輸出一致，與 Setup RR 分開顯示 |
| entry＝stop，或 target 缺漏 | 對應 RR／股數結果標為不可計算或受限，附原因；不輸出無限大、NaN 或偽造目標價 |
| 算術案例：entry＝100、stop＝95、風險預算＝300、投入上限＝10,000、成本設為 0，其他限制均不構成約束，允許以 1 股為單位 | 股數＝60、投入＝6,000、預計價格損失＝300；此為單元驗算情境，不能拿零成本作正式績效假設 |

**待裁決／交付**：RR 權威與門檻優先順序、成本口徑、數值表示與容許誤差；交付公式／單位表、來源與仲裁表及標準案例清單。

#### 3.5.2 資料品質與有效期限（2026-11-05，v5）

**目的**：避免系統使用舊價格、不完整持倉或錯誤資產基準，產生看似精確但沒有足夠依據的股數與風險結論。

**輸入與建議行為**：

* 分別記錄行情時點、SR 計算時點、資金確認時間、持倉／交易紀錄涵蓋期間與分析產生時間，不能只用「今天產生」代表所有資料都新。
* 依資料用途決定有效期限與交易日口徑；日線分析與盤中參考不可混稱即時可成交價格。
* entry／stop／target 使用可比較的價格基準，除權息與還原價格的換算規則須一致，不能把不同基準直接帶入 RR。
* 分開呈現市場資料品質與個人資料完整度。使用者未登錄交易，不等於空手、沒有未成交委託或沒有虧損；明確確認為零的資料與未知須可區分。

**資料不足或異常時**：仍可顯示有效的市場分析；使用者另填假設資金時可做條件式試算，但須標明假設。
缺少個人資金或持倉依據時，不輸出已確認的可新增股數或整體安全結論；受影響欄位標未知，而非整頁一律無法查看。

| 候選驗收案例 | 預期結果 |
|---|---|
| 行情有效，但未提供資金與持倉 | 保留有效 RR／價格分析，個人化額度標無法判定；可另做明示假設的試算 |
| 資金資料已超過核准有效期限 | 標明基準時間與過期原因，不把分析刷新時間當成資金重新確認時間 |
| entry 與 stop 使用不同除權息價格基準，或資料含分析時點之後的交易事件 | 不直接計算相互矛盾的結果；需換算／排除未來事件，並保留限制原因 |

**待裁決／交付**：各資料有效期限、完整度如何由使用者確認、價格基準與換算方式；交付必要資料清單、缺漏處理矩陣及時間／來源呈現規格。

#### 3.5.3 部位、曝險試算與風險提示（2026-11-05，v5）

**目的**：把「少量」轉成有根據的金額與股數，並讓使用者看見單筆、同股累計與多股共同預算的關係。

**輸入與建議行為**：

* 採用裁決後的資金基準及比例，分別計算投入金額上限與預計損失上限，再合併可用現金、既有持倉、最小交易單位與成本限制。
* 呈現本次建議新增、依紀錄估計的既有持有、試算後累計與真正限制股數的原因；額度是上限，不是要求買滿的目標。
* 多股組合使用同一份資金與持倉快照，固定配置順序或分配規則，列出組合合計金額與風險；各股獨立試算不能視為同時全部可買。
* 頻率、冷卻與連虧提示由已登錄交易推導，保留事件時間、計數口徑及恢復條件；分析次數不算交易次數。
* 可選的虧損／回撤提示依核准口徑計算，排除入出金的干擾；僅影響建議與提示，不執行任何外部交易。

**資料不足或異常時**：總曝險包含缺停損的持倉時，不能把該持倉風險算成零；顯示已知部分及未知部分。
交易歷史不完整時，不宣告頻率合格、連虧歸零或冷卻已解除；預算已超額時顯示原因及核准的建議處理，仍保留減碼／退出資訊。

| 候選驗收案例 | 預期結果 |
|---|---|
| 金額上限允許較多股，但停損風險上限只允許較少股 | 採較少股，顯示風險預算為限制來源；取整及成本重算後仍不超出建議上限 |
| 兩股獨立試算都可投入同一筆剩餘資金 | 組合試算不得重複配置；讀取、刷新兩份分析不扣款、不建立額度預留 |
| 已知持倉缺停損，或交易歷史未確認完整 | 市值仍可估算，相關總風險或頻控結論標為部分已知／無法判定，不呈現全部安全 |

**待裁決／交付**：資金基準與百分比、同股及總額度、組合分配方式、頻率與暫停提示門檻；交付試算流程、限制原因表與單股／組合呈現案例。百分比細節沿用「5.5」。

#### 3.5.4 人工紀錄檢核與更正（2026-11-05，v5）

**目的**：降低重複登錄、錯誤費稅、補登順序及帳務更正造成的持倉與風險提示誤判；沿用現有帳本，不建立券商自動對帳系統。

**輸入與建議行為**：

* 沿用既有交易事件與持倉投影，核對所屬 portfolio、股票、事件種類、股數、價格、費稅與實際發生時間；不把建議快照轉成交易。
* 區分同一登錄請求的重試與兩筆內容相同的真實交易；防重複依據須在正式方案定義，不能只因同時、同價、同股數就合併。
* 檢查賣出數量、部分賣出及分批進出對已登錄持倉的影響；本期沿用既有持倉模型，不藉檢核工項新增放空或融資交易模型。
* 更正與補登須沿用不可變帳本的既有語意，保留原事件與更正關係；更正影響後續持倉、損益或頻控時需重新推導並可追溯。
* ADJUSTMENT 仍是帳務校正，不計作真實買賣、不製造已實現盈虧；也不作為清除虧損歷史的捷徑。

**資料不足或異常時**：來源不明的開倉餘額可用於持倉估算，但不足以推定完整交易歷史。
疑似重複、持倉衝突或費稅缺漏須提出可理解的原因與確認／更正途徑，不能靜默刪交易或默認成本為零；處理規則待正式裁決。

| 候選驗收案例 | 預期結果 |
|---|---|
| 同一筆人工登錄因網路重試提交兩次 | 依核准防重複契約只影響帳務一次；兩筆獨立確認的相同內容交易仍能分別登錄 |
| 先登錄部分賣出，後補登較早的買進或更正費稅 | 依事件時間與核准更正規則檢核／重算，保留前後差異與原因；不默默改寫既有分析快照 |
| 沒有交易紀錄但有 OPENING_BALANCE，或新增 ADJUSTMENT | 持倉與歷史完整度分開呈現；不憑此宣告從未虧損，也不增加交易次數或清除連虧提示 |

**待裁決／交付**：重試識別、更正方式、事件排序與衝突處理、部分平倉如何組成完整交易；交付登錄／更正案例及受影響分析的更新規則。

#### 3.5.5 建議說明與可追溯性（2026-11-05，v5）

**目的**：讓使用者理解建議的依據與適用條件，並在結果有疑問時重現當時運算，定位資料、政策或程式差異。

**輸入與建議行為**：

* 主要畫面呈現建議動作、股數、投入金額、預計損失、RR、資料時間與主要限制原因；資金來源與成本假設可展開查看。
* 分開標示資料不足、策略不合格、預算不足及有效零部位建議，不能全部顯示為同一個「不買」而沒有原因。
* 生成的建議只代表該時點與假設；不得顯示成已送單、已成交、資金已鎖定或帳戶已受保護。
* 保存足以重現的輸入快照或不可變資料版本、策略／程式版本、成本政策、計算結果與原因；單存當下價格或程式版本不足以重現資金與持倉狀態。
* 資料補登或策略更新後產生新分析並關聯舊結果，保留前後差異；歷史結果不以目前資料覆蓋，使用者只能存取自己權限範圍內的資金與紀錄。

**資料不足或異常時**：有條件式假設就直接標示假設；歷史輸入不完整而無法精確重現時，應說明缺少什麼，不宣稱驗算一致。
重現當時建議與採新資料重新評估是兩種操作，須分開標示，避免用未來資訊解釋當時決策。

| 候選驗收案例 | 預期結果 |
|---|---|
| 同一資金、持倉、行情與策略快照重新計算 | 在核准精度內得到同一結果；若不一致，能識別輸入或版本差異 |
| 最新資金或補登交易使新建議股數改變 | 新舊建議各保留原依據，顯示變動原因；舊快照不被改成新股數 |
| 缺資金與已確認資金不足兩種情境 | 分別顯示無法判定與預算不足；前後端原因一致，且不洩露其他 portfolio 的資料 |

**待裁決／交付**：主畫面必要資訊、原因呈現、快照最小保存內容與期限、歷史重現能力；交付建議範例、原因對照表與快照契約，不先決定新增 API 或資料表。

#### 3.5.6 離線驗證、壓力情境與觀察（2026-11-05，v5）

**目的**：分開驗證「工具是否算對」與「建議策略是否有足夠證據」，降低正常情況可用、遇到資料或行情異常就誤導的風險。

**輸入與建議行為**：

* 依前五項的人工標準案例驗證公式、資料完整度、帳務、限制原因與前端呈現；先做變更模組的針對性檢查，再依實際影響決定整合驗證。
* 在隔離環境模擬來源逾時、資料過期、部分讀取失敗、分析重試、服務重啟與人工紀錄更正，檢查未知狀態及歷史紀錄是否正確保留。
* 模擬成交價偏離分析價、跳空越過停損、滑價擴大、無法成交及多股同步下跌；未成交不能計作已實現交易，資料不足的壓力情境須標明假設。
* 策略效益依「5.3」的時序驗證與保留資料衡量，固定成本、成交假設與參數搜尋紀錄；I-129 舊資料只作開發／回歸比較，不重新當成未接觸的驗收資料。
* 觀察階段只收集工具輸出、資料品質與使用者另行登錄的交易結果，不把建議點閱率或按建議操作的假設當成實際績效。

**資料不足或異常時**：計算正確但交易樣本不足，應分別記錄「工程驗證通過」與「策略效益待驗證」。
沒有足夠證據時不宣告提升報酬或降低實際損失；不以少量真實資金試單補足開發測試，也不包含券商送單演練。

| 候選驗收案例 | 預期結果 |
|---|---|
| 資金讀取失敗但行情成功，或服務重啟後再次開啟分析 | 有效市場分析仍可用；不以零資金／零持倉偽造個人化結果，重啟不清除已有交易紀錄推導的狀態 |
| 模擬價格跳空越過停損，或預計進場根本未成交 | 損失按固定情境的可成交假設計算，不強制封頂於計畫損失；未成交另列，不灌入成功交易樣本 |
| 標準案例與畫面檢查通過，但保留資料的樣本／績效未達事先標準 | 工程結果與策略證據分開報告，維持未通過的策略限制，不為了驗收而放寬標準 |

**待裁決／交付**：壓力情境幅度、策略接受標準、觀察期間與抽查方式；交付驗證矩陣、可重現的離線量測紀錄及限制清單。現有腳本若不足，依共同流程先提腳本修改方案再確認。

六項工項的建議依賴順序是：先定計算與資料契約，再展開部位／組合試算；人工紀錄檢核與追溯設計同步銜接，最後完成跨層及策略驗證。
這是討論用順序，估工、首版取捨、具體檔案與實作排程仍待正式方案確認；不把每個候選工項都視為已確認的首版必做功能。

### 5.1 參數來源與取得建議（2026-11-05，v2）

以下整理使用者要求留存的參數評估建議，作為後續裁決與量測的依據；要求紀錄不代表已核准其中的政策或數值。

先分清兩種來源：可接受的損失、回撤與資金投入是使用者的風險政策，不能由市場資料替使用者決定；
RR 門檻、試單比例、頻率與冷卻條件則可提出候選值，用交易資料估計效益，最後在風險政策內裁決。
不預設每日幾次、冷卻幾天或連虧幾次就是合理，也不把目前 50% 視為已驗證的最佳比例。

| 參數 | 建議取得方式 | 評估重點 |
|---|---|---|
| 單筆試單風險上限 | 使用者先定可接受的單筆損失預算，再依停損距離、成本及滑價換算股數 | 計畫風險與跳空／成交不利時的實際損失分開報告 |
| 試單部位比例 | 以目前 50% 作為比較基準之一，在相同風險限制下比較候選比例 | 整體回撤、淨收益、資金占用及跨期間穩定性；不只看單筆賺賠 |
| 最低 RR | 比較不同 RR 區間的扣成本實現損益、停損率及結果不確定性 | 高 RR 不保證高勝率或正期望；避免只調到平均 RR 上升 |
| 每日／同股試單次數 | 先識別同一交易機會與重複提示，再分析重新進場次序及其增量結果 | 計入重複交易成本；不能把分析列數當成交次數 |
| 停損後冷卻 | 比較不同等待時間，以及是否要求新的結構／進場確認訊號 | 同時衡量減少的損失與漏掉的獲利，不能只憑時間到期就推定條件改善 |
| 連續虧損暫停 | 以定義一致的已實現淨損益序列，模擬候選暫停與恢復規則 | 暫停減少多少損失、錯過多少恢復行情、等待多久；不先指定固定連虧次數 |
| 整體風險上限 | 使用者設定總風險容忍度，再納入已登錄持倉、可選保留資金情境、集中度與同步下跌模擬 | 未掌握的外部交易須揭露；單筆合格不代表多股組合也合格 |

### 5.2 優先由風險預算反推股數（2026-11-05，v2）

候選方向是先定風險預算，再求符合所有限制的最大可交易股數；試單比例可作額外上限，兩者關係仍待裁決。

```text
q × 預估每股停損損失 + C_loss(q) ≤ 可新增風險預算

q 同時受以下條件限制：
可用現金、單檔剩餘部位額度、試單累計上限、portfolio 剩餘風險額度。
```

`q` 為本次新增股數；`C_loss(q)` 為該股數在停損情境下的費稅與執行成本，
與每股損失中的滑價假設不得重複計入。額度依已登錄持倉與使用者提供的保留資金情境估算，細部口徑待正式設計；
資訊不足時不能宣稱已扣除所有實際委託。單純產生本次建議不扣除額度。
最低收費使成本可能不是股數的固定倍數，因此須按可交易單位取整後重算；不足最小單位時不強制產生一筆交易。
這個限制控制的是計畫損失，跳空、流動性不足或成交滑價仍可能使實際損失超出預算，須另做壓力情境量測。

### 5.3 參數校準與驗證流程（2026-11-05，v2）

1. **先定目標與接受標準**：量測前固定扣成本淨收益、最大回撤、資金占用、交易次數、極端損失與樣本充分性要求。
   記錄與既有策略的比較基準，不在看到結果後放寬標準，也不只挑勝率或總獲利最高的組合。
2. **建立交易與 portfolio 模擬**：依事先固定的模擬成交／未成交規則，納入持倉、現金、成本與重新進場假設；
   這是評估建議策略的離線模型，不建置券商委託生命週期系統。
   同一段行情的連續訊號及重疊持有期間不能直接當成獨立交易；以去重後交易及行情群組評估結果不確定性。
3. **依時間分段校準與驗證**：較早資料產生候選值，後續期間驗證；保留未參與選參數的最終資料。
   前瞻結果觀察區間跨越分界時，須排除重疊或留足間隔，避免未來結果滲入校準資料；並分期間與股票檢查穩定性。
4. **控制搜尋範圍並留存所有嘗試**：先評估少量有明確理由的候選值，記錄參數組合、資料版本及成功／失敗結果。
   偏好相鄰設定都能維持表現的區間；若只有單一精確數值有效，應調查過度調參，而非直接採用歷史最佳點。
5. **固定候選方案後再驗收**：在保留資料上檢查效益、風險與不確定性；證據不足則維持待驗證。
   若再根據驗收結果調參，該資料即成為開發資料，須另留新的驗證證據。後續可規劃模擬成交／觀察追蹤，實作與部署仍須另行確認。

方法參考：[scikit-learn 時序切分與間隔說明](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)
說明依時間切分及 `gap` 的用途；[Bailey 等人的回測過度擬合研究](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)
說明大量候選回測的選擇偏誤。單次保留測試集不能取代對搜尋次數、資料重用及結果穩定性的檢查。

### 5.4 I-129 證據限制與建議順序（2026-11-05，v2）

I-129 正式試單放寬量測的新放行組平均實現 R 為負（約 −0.170），且另有樣本不足問題，詳見
[`sr-zone-scoring.md`](../sr-zone-scoring.md)「進場許可的 RR 判斷看 execution gate」的量測與退回紀錄。這個 −0.170 是混合口徑、未扣成本的模擬值（I-130 的 R4），⛔ 不是淨交易績效。
縮小該組部位本身只改變損益幅度，不能據此宣稱交易期望已改善；額外成本還可能改變縮放後的結果。
若以冷卻、頻率或確認條件篩選交易，須另驗證篩選後的效益，並遵守重新開放試單的門檻（見「一」末段）。

既有 replay 是進場許可逐列量測，不能直接當成共享資金、實際持倉與交易頻率策略的完整回測。
已反覆參與 I-129 開發與 review 的資料，於 T-080 應定位為開發／回歸比較資料，不能再宣稱為未接觸的最終驗證集。

建議先評估「風險預算換算股數、同一交易機會去重、整體風險上限」，再評估冷卻與連虧暫停；
此順序是規劃建議，尚未核准實作，也不改變既有進場門檻。
後續所需輸入包括使用者資金／可用現金、可接受的損失與回撤、商品及券商成本、已登錄持倉與可靠交易歷史；
資料缺漏須列為校準限制，不能以零成本、零持倉或沒有外部委託默認補齊。資料完整度影響可提供的個人化結論，不把完整登錄所有交易當成查看市場分析的先決條件。

### 5.5 按資產或投入預算百分比浮動額度（2026-11-05，v3）

使用者要求將本議題加入規劃書，留待開發討論：金額上限可評估以「資金基準 × 百分比」產生，
並隨所選基準變動；目前只記錄候選方案，不決定比例、更新規則或實作方式。

| 候選方式 | 計算概念 | 開發時待討論 |
|---|---|---|
| 按交易帳戶淨值 | 帳戶淨值 × 試單配置比例 | 淨值的範圍、估值來源、負債及未實現損益如何納入 |
| 按預計投入資金 | 本策略配置資金 × 試單配置比例 | 配置資金是固定核定預算、實際撥入金額或隨策略盈虧變動的淨值；尚未到位的資金不能當可用現金 |
| 分層配置 | 帳戶淨值 × 策略配置比例 × 試單配置比例 | 策略間如何配置，依已登錄持倉與可選保留資金情境估計剩餘預算，避免組合試算重複配置 |

分層配置為候選方向，可搭配「投入金額」與「預計損失」兩項限制：

```text
策略預算 = 交易帳戶淨值 × 策略配置比例
每筆試單金額上限 = 策略預算 × 試單配置比例
每筆預計損失上限 = 策略預算 × 單筆風險比例
```

試單配置比例與單筆風險比例是不同參數，不得混用。
同一投入金額在不同停損距離下會產生不同的計畫損失，最終股數仍須依「5.2」同時滿足含成本的金額、風險、
可用現金及剩餘額度限制；不得把試單金額上限解讀為每次都應買滿的目標，也不得用浮動額度覆蓋進場等待或阻擋。

開發討論至少須裁決：

1. **基準與資料權威**：候選以本交易帳戶／portfolio 的淨值為基準，釐清現金、持倉市值、負債及資金調撥的範圍；
   是否排除房產、其他帳戶及未撥入資金。帳戶淨值與實際可用現金須分開計算，缺漏或估值過期不能默認為可用額度。
2. **固定或浮動預算**：策略預算固定核定時，帳戶淨值變動不必然同步調整該預算；若隨淨值浮動，須定義盈虧、入金及出金的更新政策。
   各候選方案須用同一交易資料比較，避免把入金造成的金額增長誤認為策略報酬。
3. **更新時點與可追溯性**：評估每日固定時間與逐次分析重算的取捨，呈現基準金額、估值時間、比例、策略版本及資料完整度。
   畫面須讓使用者知道下單前仍應自行核對最新資金、持倉及券商委託，系統不提供送單前強制檢查。
4. **累計與共同額度**：明確定義每筆、同股累計及整個策略／portfolio 的建議上限，依已登錄持倉估計剩餘額度。
   多股組合須使用同一資金快照；不同畫面的單股建議不得解讀為可同時全部買進，刷新分析不扣款也不建立預留。
5. **額度縮減與既有持倉**：淨值下降、出金或預算縮減後，如何提示超額、停止建議新增或提出減碼建議須獨立裁決；
   本期不自動撤單或賣出，減碼／退出建議仍須保留既有仲裁邊界。

具體百分比、是否另設固定金額上限及調整速度均待使用者裁決與量測。
本節只擴充 T-080 的開發討論範圍，現有 50% 試單比例及 20 萬／1 萬設定沒有因此變更。

## 七、風險與驗證方向

| 風險／反例 | 正式測試與量測應驗證的內容 |
|---|---|
| RR 公式／價格來源互相覆蓋 | 缺 target、分母不為正、不同進場價、Go 推導目標與 Python 未知目標的情境，保留來源與合理仲裁 |
| 含成本後不再划算 | 最低手續費、不同費稅與滑價、股數取整後重算，不能只以毛 RR 判合格 |
| 小風險距離算出過大股數 | 金額、現有持倉、現金及總曝險限制仍同時生效；零股數不得強制變正數 |
| 同股重複分析或請求重試 | 重複提示不當成成交，不消耗或預留資金；人工登錄重試不產生重複帳務 |
| 多股獨立建議被直接相加 | 同一組合依共同資金快照試算；獨立單股建議明示不能直接累加，owner scope 不得混用 |
| 浮動預算與資料不同步 | 淨值、入出金、持倉估值變動後顯示一致的時間與假設；缺值標未知，不把未到位資金當現金 |
| 浮動額度縮小後持倉超限 | 按核准政策顯示超額或減碼建議，不執行撤單或強制賣出 |
| 跨日、休市與服務重啟 | 冷卻／次數／暫停狀態按核准的時區與窗口延續，不因重啟或快照刷新歸零 |
| 部分賣出、補登與帳務校正 | 虧損連續次數與損失金額有可追溯定義；ADJUSTMENT 不偽裝成交或清除限制 |
| 新增建議限制遮蔽減碼／退出資訊 | 保留結構性 AVOID、REDUCE、EXIT 與 daily 阻擋；預算或冷卻提示不得遮蔽風險降低的建議 |
| 只看漂亮樣本或忽略總成本 | 凍結輸入、完整母體、成本與成交規則、逐股及 portfolio 結果，並分開報告新增放行與既有組 |
| 樣本不足卻宣告改善 | 量測前先定樣本、風險與接受門檻；不以少量實盤或單純提高 RR 代替有效證據 |
| 跨層呈現不一致或把建議當成交 | final、action、股數、風險與限制原因一致，明示建議用途；條件式試算不得偽裝為已確認的個人化可買額度 |
| 資料不全卻顯示安全 | 區分可用市場分析與無法判定的個人化股數、曝險、頻率或連虧；缺交易紀錄不能當成從未虧損 |
| 精度、單位及行情壓力假設錯誤 | 元／股／百分比、成本及取整採人工標準案例；含跳空、滑價、多股同步下跌的離線情境不得宣稱保證停損價成交 |

後續驗證優先使用 repository 的 runtime 腳本與隔離 dev stack；涉及多資料庫 migration 或併發時，依
[`development-workflow.md`](../development-workflow.md) 選用對應驗證。實作範圍與參數未定之前不新增猜測性的交易測試或跑 live 實驗。
