## 一、目標與確認範圍

建立供人工判斷的資產配置工具，持續回答：現在持有是否符合各層目的、風險是否過度集中，以及調整後是否有足夠理由改善配置。
建議須隨時間、價格、持有金額、資產比例、資金需求與投資理由變化重新評估，而非只在買入時提供一次判斷。

使用者確認的三層為「核心、長期投資、短期波動」。每層有自己的目的、資料需求、評估週期、資金預算、加碼／減碼／退出與失效條件；
不能用同一套買賣規則只換三個比例或持有天數就當成三層策略。各層的具體定位仍須裁決，尤其核心與長期投資的差異不能僅靠名稱。

本案涵蓋：

1. 三層的初始配置、既有持倉歸屬及各自獨立的持有與調整邏輯。
2. 隨時間、價格、資產淨值、持有比例／金額及事件變化重新評估的機制。
3. 續抱、加碼、減碼、退出、保留現金與轉投其他商品的建議及比較。
4. 跨層、跨標的、產業與商品的集中／重疊曝險，以及整體配置協調。
5. 調整前後的資產配置、風險、成本、資料限制與理由的可追溯呈現。

工具只提供分析、試算與建議，由使用者人工決策並於外部操作。本期不做自動下單、券商委託追蹤、交易額度預留、自動換倉或強制清倉。
生成或接受一份建議不等於已成交，不直接改寫實際持倉／現金。人工登錄交易與配置歸屬更新的責任須在正式契約分開定義。

## 三、三層獨立判斷的候選方向

下表是供開發討論的設計方向，不是已核准的投資規則或任何特定商品的買賣建議。

| 層級 | 持有目的與獨立輸入 | 加碼評估方向 | 減碼／退出評估方向 | 評估時間與事件 |
|---|---|---|---|---|
| 核心 | 長期主要底倉與整體配置角色；配置目標、持有理由、資金需求、商品特性與集中程度 | 原有核心角色仍成立、相對核定配置不足且資金／風險允許時，評估是否補足 | 持有理由或商品角色失效、比例／集中度超限、資金需求改變時，評估再平衡或退出；核心不代表永久不能賣 | 定期配置檢視及角色／風險重大變化；週期與偏離門檻待定 |
| 長期投資 | 可持續追蹤的個股／主題投資理由；基本面、估值、發展里程碑與已登錄持有狀況 | 投資理由獲得新證據支持，估值／條件合適且累計部位仍符合預算時評估 | 投資理由被否證、里程碑未達、估值或風險條件改變時評估；不僅因短期價格波動決定 | 定期研究更新、資料發布與投資理由變化；須按當時已知資訊判斷 |
| 短期波動 | 有交易期限的波動機會；市場結構、進出價、RR、停損、持有時間與事件風險 | 交易條件及必要許可仍成立、出現核准的新證據且風險預算允許時評估 | 結構／交易假設失效、停損、目標或時間條件達成時評估 | 按資料頻率與交易事件評估；不能因虧損把失敗交易自動改歸長期或核心 |

每層須各自定義可用、資料不足、續抱、可加碼、應減碼、應退出與待人工確認等結果的語意，實際狀態名稱待契約設計。
可共用價格、成本與數值工具，但層別規則、所需證據及判斷理由必須獨立且可分別驗證。
資料未達該層所需條件時，輸出資料不足／待評估，不拿另一層的訊號假裝補足。

三層不是三種保證風險等級；核心或長期標籤本身不能降低該商品的實際集中曝險。
共同風險需要減碼時仍可提出核心部位的調整候選，但須保留「核心自身判斷」與「整體風險調整理由」兩份依據。

## 四、層別歸屬、持倉及資金口徑

* 每份配置部位須標示所屬 portfolio、商品、層別、數量、配置理由、生效時間及策略版本。是否用子部位、分配表或其他模型，待正式方案裁決。
* 同商品可以跨層持有，但各層分配數量合計須與實際已登錄持倉對得上；未完成分類時列為「未分類」，不得重複分配或默認全屬核心。
* 跨層轉移須由使用者明確確認，留下原／新層別、數量、理由與時間；只是歸屬變更時不視為實際買賣、不改變總股數／現金，也不憑空產生損益。
* 分層成本、持有期間、已實現／未實現損益及稅費歸因，須與既有 AVG 帳本對帳；不能直接把合併平均成本當成已驗證的各層真實成本。
* 定義配置分母：投資帳戶淨值、策略可配置資產或其他核定基準，並分清可用現金、保留資金、負債及外部未納入資產。
* 配置呈現須包含三層、現金與未分類／未估值項目；缺價不能把市值設為零後宣稱完整配置或比例已達標。已知範圍的百分比須標明分母。
* 多幣別須固定基準幣別、匯率與估值時間；跨帳戶彙總須處理授權與同一實際資產重複登錄，不默認所有 portfolio 都可合併。

目標比例、容許區間、最低現金與單股／產業／商品上限均待裁決，不在本次填入任意比例。
「核心」與「長期投資」的標的與角色界線、現金是否分層配置亦須明定，避免同一份資金在不同層重複可用。

## 五、動態評估與整體協調資料流

```text
資金／持倉／層別歸屬快照 ＋ 價格／匯率／成本 ＋ 各層所需投資證據與政策
                              ↓
                  資料完整度、時間與估值基準檢查
                              ↓
          核心獨立判斷 ｜ 長期投資獨立判斷 ｜ 短期波動獨立判斷
                              ↓
          整體配置協調：共同資金、集中／重疊曝險、現金需求與衝突說明
                              ↓
         維持現況／加減碼／退出／保留現金／轉投商品等候選方案比較
                              ↓
         建議、金額／比例、依據、調整前後影響、限制與下次檢視條件
                              ↓
             人工決策；實際交易與配置歸屬按各自契約另行登錄
```

### 5.1 何時重新評估

候選觸發包括定期檢視、價格／配置比例偏離、單一標的金額增加、集中風險上升、資金需求／入出金改變、
投資理由或商品特性變化，以及新交易登錄、持倉更正或層別歸屬更新。具體門檻、資料頻率與更新排程待裁決。

時間到期或價格波動只觸發重新評估，不直接等於必須交易；結果可以維持現況。
須設計提醒去重、最短重評間隔與觸發／解除區間的候選政策，避免門檻附近反覆建議買賣；這不是券商交易冷卻或送單控管。
定期與事件觸發共用可追溯快照；資料尚未更新時不得假裝取得新證據。

### 5.2 協調原則與衝突處理

* 保留各層原始結論與理由，再列出共同預算或風險限制對建議的調整；整體層不把三層改寫成同一套交易訊號。
* 一層建議加碼、另一層建議減碼時，先核對部位歸屬、相同商品的總曝險與調整後結果；列出衝突，不能無說明相互抵銷或重分類。
* 各層獨立看來有額度時，仍須在同一資金快照下比較合併方案；不能將相同現金配置多次，也不能把預期賣出所得當成已可動用資金。
* 評估共同標的、產業、商品與可得的底層持倉重疊；資料不足時顯示未知，不能只因名稱或商品種類不同就宣稱風險已分散。
* 假設相關性、波動或風險貢獻有量化估計時，列出資料區間與估計限制，另做同步下跌情境，不將歷史估計當成保證。
* 風險提示不能遮蔽減碼／退出理由；本期僅調整建議，不執行停買、賣出、撤單或資金鎖定。

## 六、調整方案與轉投其他商品的比較

至少將「維持現況」列為基準；可比較使用新資金補足、部分減碼保留現金、層內更換商品，以及跨層調整等候選方案。
轉投評估須回答新商品在配置中扮演什麼角色、減少了哪些曝險、又新增哪些風險；不以追逐近期報酬作為唯一理由。

| 比較面向 | 候選輸出與限制 |
|---|---|
| 配置前後 | 各層、商品與現金的數量／金額／比例，估值時點與分母；列明調整幅度及取整後殘餘偏離 |
| 風險前後 | 單一商品、產業、底層重疊、可得的集中與壓力情境結果；未知部分另列，不強行排出精確名次 |
| 成本與流動性 | 賣買費稅、價差、滑價、匯兌、交易單位、流動性與交割可用時間；商品資料缺漏時不宣告淨效益較佳 |
| 資金守恆 | 模擬後現金＝原現金＋賣出所得－買入支出－相關成本；匯兌與外部現金流須明列，買賣金額不得重複計入成本 |
| 投資理由與不調整代價 | 各層理由是否仍成立、為何現在調整、維持現況的風險、調整是否會犧牲原本的配置目的 |
| 不確定性與可行性 | 假設價格及可成交性、尚待取得的資料、建議有效條件；估計改善不等於實際改善或保證獲利 |

同一估值時點、無外部現金流的純買賣模擬，總資產不應因重新分類或換倉計算憑空增加；成本須反映在模擬後淨值。
採不同商品或跨幣別方案時須統一估值基準；若無法可靠比較，保留現金或維持現況是有效候選，不強制推薦替代商品。

## 七、資料不足、建議呈現與追溯

* 市場分析、假設情境與基於使用者真實登錄資料的配置評估分開呈現；缺持倉、現金或層別資訊時，不能顯示全帳戶已安全。
* 基本面／估值資料不足時，長期投資判斷標為待資料；核心理由未定時不自動套用短期停損；短期層仍須遵守自身必要證據與有效許可。
* 股數與平均成本已知不代表三層歸屬已知；人工持倉帳本也不代表涵蓋所有外部交易與未成交委託。
* 建議須呈現所屬層、原層別結論、整體調整理由、建議數量／金額／比例、成本假設、資料時間與完整度，以及失效／下次評估條件。
* 同一商品的不同層建議分開顯示，再提供合併曝險與方案效果；不將跨層賣出建議誤解為全部持倉都該賣。
* 保存資金、持倉、層別、價格、投資理由與政策版本的可重現快照；資料更正後產生新評估，歷史結果保留當時依據。
* 不為了查看基本分析而強制使用者完成全部帳務；條件式試算須明示假設，個人化配置結論則依可用資料限制呈現。

## 九、風險與候選驗收案例

| 案例／風險 | 驗收方向 |
|---|---|
| 同商品核心續抱、短期退出 | 各層理由獨立，退出量限於對應層別的候選方案；合併曝險仍正確，整體若另需減碼須明示理由 |
| 短期虧損後改列長期 | 不自動轉層；人工確認轉層時留存理由、原層交易結果與前後歸屬，不掩蓋失敗或製造收益 |
| 同商品三層重複分配 | 層別合計不超過已登錄總持倉，未分類另列；部分賣出及補登後能重算或標示衝突 |
| 時間經過但價格不變 | 按該層週期、投資理由與持有期限重評；不憑經過時間就一律買賣 |
| 價格上漲導致占比／金額超限 | 分清價格變動、目標變更及入出金，產生有理由的減碼／再平衡候選，不能因漲價就無條件加碼 |
| 基本面未更新但短期 SR 轉佳 | 長期資料不足仍標待評估，不能用短期利多冒充長期投資理由已成立 |
| 三層各有可買訊號但共用現金不足 | 單一資金快照下協調並比較方案，不重複配置；不預留資金或修改真實持倉 |
| 換買名稱不同但底層相近的商品 | 檢查可得的底層／產業重疊，不能直接宣告分散；缺資料時風險改善標未知 |
| 轉投商品缺報價、費率或幣別資訊 | 不給已確認的精確調整量／淨效益，允許維持現況或保留現金作比較 |
| 換倉／轉層後資產被重複計算 | 同時點模擬符合資金與股數守恆；純轉層不產生現金或損益，換倉反映成本 |
| 提醒門檻附近反覆波動 | 依核准去重與解除政策處理，保留重評結果，不把每次提示當成交 |
| 資料過期、補登、服務重啟或無層別 | 不默認零風險或自動分類；已知部分可顯示，歷史快照不被最新資料覆蓋 |
| 權限或彙總範圍錯誤 | 依 portfolio 權限讀寫，未授權資料不納入；重複登錄的同一資產不因跨帳戶顯示而計兩次 |
| 工程通過但策略證據不足 | 各層獨立量測及合併配置結果分開報告；保留未通過項目，不宣稱已提升報酬或保護本金 |

策略驗證須先固定比較基準、成本、資料時點、再平衡規則與接受標準；各層分別報告結果，再評估合併配置的回撤、集中、換手、成本與現金需求。
依時間分段驗證，排除未來資料與重疊樣本造成的偏誤，記錄候選參數與失敗結果；長期策略不能僅以短期行情通過測試就宣告有效。
必要資料或歷史不足時，工程正確性與策略效益分開標示。本期先用離線模擬與分析觀察，不用真實資金代替開發測試。
runtime 驗證優先使用既有腳本與隔離 dev stack，依 [development-workflow.md](../development-workflow.md) 執行；腳本能力若不足，先提修改方案確認。
